# Конфиги и файлы данных

Краткий справочник: какие входные файлы задают правила игры, и какие файлы/данные генерируются
во время и после сессии. Не заменяет `SPEC.md`/`BUILD_PLAN.md` — просто карта того, что лежит на
диске и в каком формате.

## 1. Входные конфиги

### 1.1 Какие файлы есть

- **`src/Game.Config/Samples/gameconfig.pilot.json`** — боевой пилотный конфиг, предложен по
  умолчанию на `/admin`.
- **`src/Game.Config/Samples/gameconfig.training.json`** — короткий тренировочный пресет: те же
  секторы/материалы, что и в пилотном, но всего 8–10 ходов и тайминг фаз «по минуте» (расчёт 5с +
  решения 45с + завершение 10с = 60с/ход) — для обкатки процесса, не для реальной игры.
- **Свой файл** — администратор может загрузить произвольный JSON той же формы через `/admin`
  (кнопка выбора файла) вместо одного из двух образцов выше.

Загрузка идёт через `GameConfigLoader.Load`: сначала `GameConfigValidator.Validate` (проверяет
ссылочную целостность — не ссылается ли рецепт на несуществующий материал, нет ли циклов
производства и т.п.; на ошибке — `GameConfigValidationException` с человекочитаемым сообщением,
конфиг не применяется), затем `GameConfigResolver.Resolve` превращает сырые строковые id-ссылки в
прямые объектные ссылки (`ResolvedGameConfig`) — с этого момента граф материалов гарантированно
без циклов и без висячих ссылок.

### 1.2 Из чего состоит один конфиг

Один JSON-файл — это один объект `GameConfig` (`src/Game.Config/GameConfig.cs`) из ~15 разделов:

| Раздел | Что задаёт |
|---|---|
| `Sectors` | Секторы экономики |
| `Materials` | Справочник материалов (id, имя, сектор, уровень передела) |
| `Recipes` | Рецепты переработки (выход, вход(ы), количества, скорость производства) |
| `FactoryDefinitions` | Типы фабрик — свой сектор, доступные рецепты, стоимость постройки/ликвидации, капитальные затраты за ход (содержание фабрики вне зависимости от выпуска) |
| `StartingConditions` | Стартовые условия команды (баланс, кредит), включая потолок долга по принудительному займу |
| `SessionPresets` | Пресеты длительности — диапазон ходов `[MinTurns, MaxTurns]`, справочная длительность хода в минутах. Точный ход окончания разыгрывается случайно внутри диапазона один раз при старте сессии |
| `PhaseTiming` | Длительность фаз хода (расчёт/решения/завершение), одна на весь конфиг — общая для всех пресетов |
| `Economy` | Цены/ёмкость рынка по материалам, тренды, маржа переделов, расход электричества на единицу выпуска (переменная часть затрат на работу фабрики), базовый и «давящий» (растущий с недавними закупками команды, затухающий по полураспаду) множители аварийной закупки |
| `WorkerProductivity` | Как число рабочих влияет на производительность фабрики; зарплата — прогрессивная по общей численности команды сверх настроенного порога |
| `Rnd` | R&D — накопительные пороги вложений в фабрику и прирост скорости производства за уровень (линейная прокачка, без веток), плюс потолок вложения за ход на одну фабрику |
| `Wear` | Износ и капремонт фабрик — льготный период, ускоряющаяся с возрастом скорость декея, штраф к содержанию по мере износа, ступени действия «Капремонт» (`OverhaulTiers`: порог состояния, цена, простой, множитель к выпуску, тарифы зарплаты/содержания на время простоя — от лёгкого обслуживания до полной реконструкции), критический порог и параметры вынужденного простоя движка (safety net на случай полного игнора) |
| `GenerationResearch` | Командное (не пофабричное) исследование, разблокирующее доступ к постройке более глубоких переделов пирамиды сырья — нелинейная (вогнутая) отдача от накопленного вложения, потолок за ход на команду |
| `Warehouse` | Склад — вместимость, плата за хранение |
| `Reputation` | Параметры репутации |
| `Contracts` | Параметры сделок между командами |
| `Taxes` / `Deposits` | Налоги и депозиты (действуют только если включены `FeatureFlags`) |
| `News` | Библиотека заголовков новостной ленты |
| `FeatureFlags` | Какие механики MVP включены |

Полная цепочка материалов (сектора/материалы/рецепты) в любом загруженном конфиге теперь видна
целиком на странице `/materials` — SVG-диаграмма с цветом по сектору и количествами на рёбрах.

## 2. Выходные файлы

### 2.1 На диске (`App_Data`) — состояние процесса

Не «файл настроек», а *event-sourced журнал*: каждое действие (заведение команды, сделка, ход,
регистрация участника и т.д.) — отдельная запись, состояние всегда получается полным
воспроизведением журнала с начала, а не хранится напрямую. Это то самое «достаточно, чтобы
проиграть систему от и до», о чём шла речь раньше в этом разговоре.

Две независимые области, у каждой одна и та же тройка файлов:

- **`App_Data/draft/`** — черновик настройки до старта сессии (команды, персонал/администратор,
  выбранный конфиг). Открывается сразу при старте процесса, переживает перезапуск.
- **`App_Data/session/`** — активная (или уже завершённая) игровая сессия целиком: команды,
  участники, сделки, ходы, рынок, всё. Появляется только после «Начать сессию».

Файлы внутри каждой области:

| Файл | Формат | Назначение |
|---|---|---|
| `journal.jsonl` | JSON Lines — одна запись-событие на строку | Собственно журнал. Каждая строка: `SequenceNumber`, `Timestamp`, `ChangeType` (полное имя .NET-типа события), `ChangeJson` (сериализованное событие), `PreviousHash`/`Hash` (SHA-256 хеш-цепочка — при чтении проверяется целостность, повреждённая/подменённая запись рвёт цепочку и обнаруживается) |
| `config.json` | Обычный JSON, та же форма, что и входной конфиг | Выбранный `GameConfig` этой области — не событие (объектный граф каталога не проходит через `System.Text.Json` напрямую), поэтому хранится отдельным файлом и перечитывается через тот же загрузчик, что и входные конфиги |
| `snapshot.json` | JSON | Существует в коде (`DurableEventLog.Snapshot()`), но нигде не вызывается в проде — восстановление всегда идёт полным воспроизведением журнала, а не по снапшоту |

При «Сбросить всё в ноль» (hard reset) и при старте сессии из черновика старые файлы не
удаляются, а переименовываются в `*.{таймстамп}.bak` — история физически остаётся на диске, даже
если её забыли выгрузить через экспорт ниже.

Категории событий в журнале (полный список — файлы `src/Game.Engine/*.cs`, суффикс не
`State`/`Config`): заведение и удаление команд/персонала (`TeamStaged`, `ParticipantRegistered`,
`ParticipantStaged`, …), сделки (`ContractSigned`, `ContractConfirmed`, `ContractDelivered`,
`ContractTerminated`, …), фабрики и производство (`FactoryBuilt`, `FactoryLevelAdvanced`,
`FactoryProduced`, `RndInvested`, …), рынок и финансы (`MarketUpdated`, `MarketPriceAdjusted`,
`LoanTaken`, `LoanInterestCharged`, `SalariesPaid`, `WarehouseFeeCharged`, …), ходы и фазы
(`SessionStarted`, `PhaseAdvanced`, `PhaseExtended`, `SessionPaused`/`Resumed`, …), доска
потребностей и новости (`NeedPosted`, `NewsPublished`, `GrantIssued`, …).

### 2.2 Экспорт «на скачивание» (дебриф, Блок 10.1 SPEC §12)

Доступно ведущему и администратору (`/admin` → «Печатные материалы» / доска ведущего) после старта
сессии — обычные HTTP-эндпоинты, не сохраняются на сервере, отдаются прямо в браузер:

| Эндпоинт | Формат | Содержимое |
|---|---|---|
| `/export/journal.json` | JSON, с отступами | Тот же журнал сессии, что и `App_Data/session/journal.jsonl`, но human-readable: короткое имя типа события вместо полного .NET-имени, без хеш-цепочки. Не предназначен для обратной загрузки — только для анализа/аудита без программиста |
| `/export/turns.csv` | CSV | По одной строке на ход: `Turn, TotalCash, VolumeSoldToSystem, ForcedLoanCount` — сводка динамики по ходам всех команд |
| `/export/scores.csv` | CSV | По одной строке на команду: `TeamName, Cash, Debt, WarehouseValue, FactoriesValue, Score` — итоговый результат на момент выгрузки |

CSV — запятая как разделитель, английские PascalCase заголовки, числа в инвариантной культуре (точка, не запятая).
